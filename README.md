# Нотная тетрадь

Web app for writing violin parts on iPhone: enter notes on a staff, listen to them, print a PDF. Installed from Safari to the home screen and works offline.

Live: https://alex-drop2201.github.io/notnaya-tetrad/

## Branches

- **`source`** (this branch) — the source code. All work happens here.
- **`main`** — the built site that GitHub Pages serves. Generated by `npm run deploy`; never edited by hand.

## Develop

```sh
npm ci
npm run dev        # local server with hot reload
npm run build      # typecheck + production build into dist/
npm run preview    # serve dist/ locally
```

## Publish

Commit and push your changes to `source`, then:

```sh
npm run deploy
```

This builds the app and pushes `dist/` to `main`. GitHub Pages picks it up in a minute or two, and the installed app on the phone updates the next time it is opened online (the service worker caches a new version).

## Stack

Vite, React 19, TypeScript, Tailwind CSS 4, shadcn/ui (Radix, vaul, sonner), VexFlow 4 for engraving, jsPDF + svg2pdf.js for the PDF, Web Audio with violin samples for playback.

```
src/
  lib/          data model and logic, no React (score edits, pitch, durations, storage, engraving, PDF, audio)
  editor/       editor state, staff, piano, toolbar
  screens/      library, new part, part settings, editor
  components/   shared UI; ui/ holds the shadcn primitives
public/         manifest, icons, violin samples (src/sw.js is the service worker template)
deploy/         README and CLAUDE.md copied into the `main` branch on deploy
scripts/        deploy script; scripts/samples: how the violin samples were made
docs/AUDIT.md   design audit (Impeccable) and what was fixed
.claude/        Impeccable design skill for Claude Code
```

Parts are stored only on the device (IndexedDB `notnaya-tetrad` / `scores`). The format is `Score` in `src/lib/types.ts` with `schemaVersion: 1`; keep it backward compatible.

A part can have a second part on a staff under it (`Score.second`, «Добавить вторую партию» in the editor's menu): both staves are drawn joined by a bracket, play together and print together or one at a time. Edits of the second staff run on the score with its staves swapped (`staffView` in `src/lib/score.ts`); measures are added, copied and removed on both staves at once.

## History

The original source was not in GitHub; only the build was. This source was reconstructed from that build (deminified by hand, same libraries and versions) and checked against it in a browser: the same 31-step editing scenario gives identical staff SVG, UI state and stored data.
